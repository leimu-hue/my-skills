# 项目文档生成器

根据项目代码自动生成完整的项目文档套件，输出到 `Doc/<需求名称>/`。

## 适用与边界

### 适用场景
- 新项目快速生成标准文档
- 老项目补齐历史文档
- 交付前统一文档格式与版本信息

### 非适用场景
- 用户只要求修改单篇文档而非生成整套文档
- 项目代码或目录不可访问
- 用户明确要求输出格式与本 Skill 固定模板冲突（需先确认）

## 输入要求

- 目标项目目录（必需）
- 需求名称（必需，用于目录名）
- 项目名称（建议，缺省可由目录名推断）
- 输出语言（默认中文）
- 是否读取 Git 信息（默认开启）

## 执行原则

- 仅基于可见代码与仓库信息生成内容，不臆造不存在的模块、表、接口。
- 若信息不足，在文档中显式标注“待确认/待补充”。
- 目录已存在时，先读取已有文档并在不破坏原结构前提下增量补全。
- 默认生成 Markdown 文件，不额外生成二进制格式。

## 工作流程

### 1. 理解项目代码
- 分析项目目录结构
- 优先读取入口层、应用层、领域层、基础设施层核心文件
- 识别领域模型、数据仓储、业务流程与外部依赖
- 提炼模块边界与关键数据流

### 2. 版本信息获取
- 检查是否为 Git 仓库
- 提取提交次数与最近提交记录（若可用）
- 按“版本号规则”生成版本号

### 3. 作者信息获取
生成文档时，作者字段按以下三级优先级获取：
- **第1优先级 — 当前用户**：获取调用 Skill 的用户标识（PowerShell: `$env:USERNAME`，Linux/macOS: `whoami`）
- **第2优先级 — Git 提交作者**：从目标项目的 Git 最近一次提交中提取作者名（`git log -1 --format=%an`）
- **第3优先级 — 置空**：若以上均无法获取，作者字段留空（`作者：` / `Author: `）

### 4. 创建文档目录
在项目根目录下创建 `Doc/<需求名称>/`（如已存在则检阅现有文档作为参考并增量更新）。

### 5. 生成文档套件

按顺序生成以下 7 份文档：

| 序号 | 中文文档 | 内容要点 |
|------|---------------------|----------|
| 01 | 需求规格.md | 功能概述、功能需求清单、业务规则需求、非功能需求 |
| 02 | 概要设计.md | 系统架构、模块划分、类图关系、核心流程概要、依赖关系 |
| 03 | 详细设计.md | 每个方法的算法流程、分支逻辑、关键实现细节 |
| 04 | 数据库设计.md | 数据表结构、字段定义、表间关系、索引建议 |
| 05 | API文档.md | 接口清单、入参出参、调用示例、异常场景 |
| 06 | 测试计划.md | 单元测试用例、边界条件、并发测试、测试数据准备 |
| 07 | 部署手册与用户手册.md | 环境要求、配置项、部署步骤、操作指南、常见问题 |

### 6. 版本管理

#### 版本号规则
- **有 Git 版本控制**：`1.{yy}.{Mdd}.{git提交次数}`
- **无 Git 版本控制**：`1.{yy}.{Mdd}.{hmm}`

字段约定：
- `{yy}`：年份后两位
- `{Mdd}`：月份不补零 + 日期补零
- `{git提交次数}`：`git rev-list --count HEAD`
- `{hmm}`：小时不补零 + 分钟补零

#### Git 提交记录提取
- 使用 `git rev-list --count HEAD` 获取总提交次数
- 使用 `git log --pretty=format:"%h - %s (%an, %ar)" --date=short` 获取最近提交记录
- 提交记录用于生成变更日志和版本历史；无法获取时使用“初始版本”占位

#### 变更日志格式
在每个文档头部包含变更日志：

```markdown
## 变更日志

| 版本 | 日期 | 作者 | 变更内容 |
|------|------|------|----------|
| 1.26.509.1234 | 2026-05-09 | <动态获取> | 初始版本 |
| 1.26.510.1250 | 2026-05-10 | <动态获取> | 新增XXX章节，修正XXX描述 |
```

### 7. 文档头部信息

每个文档必须包含：

```markdown
# 文档标题

**项目名称**：XXX项目
**作者**：<动态获取>
**日期**：2026-05-09
**版本**：1.26.509.1234

## 变更日志
...
```

> **说明**：作者字段通过"3. 作者信息获取"中定义的三级优先级动态获取，不再使用硬编码的固定作者名。

### 8. 内容质量规则

- 需求规格中的功能点需与代码中的模块/接口可追溯。
- 概要设计需体现模块职责与依赖方向，避免仅罗列文件名。
- 详细设计需覆盖关键方法的输入、处理、输出与异常路径。
- 数据库设计需区分“已存在表结构”和“建议优化项”。
- API 文档需标注鉴权、请求参数、响应示例与错误码。
- 测试计划需至少包含正常、边界、异常三类用例。
- 部署与用户手册需区分“部署步骤”和“操作说明”。

### 9. 输出收尾

- 返回生成结果摘要：输出目录、文件清单、版本号来源（Git/时间）。
- 对缺失信息给出待确认项列表，便于下一轮补全。
