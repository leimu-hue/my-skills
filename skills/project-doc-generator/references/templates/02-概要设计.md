### 4.1 变更流程时序图（必填）
[要求：必须包含“变更前置校验 -> 变更执行 -> 分支处理 -> 返回结果”；可按实际模块替换参与者名称]

```mermaid
sequenceDiagram
	actor U as 用户
	participant FE as 前端页面
	participant C as XXXController
	participant AS as ApplicationService
	participant DS as DomainService
	participant R as Repository

	Note over U,FE: 入口：用户触发“修改/提交变更”动作
	U->>FE: 提交变更请求
	FE->>C: POST /xxx/change

	Note over C,AS: 适配层：参数校验、鉴权、幂等校验
	C->>AS: change(cmd)
	AS->>DS: validateAndChange(cmd)

	Note over DS,R: 领域层：读取当前状态并校验可变更条件
	DS->>R: 查询当前实体/版本
	R-->>DS: 返回实体快照
	DS->>DS: 校验状态机、版本、并发条件

	alt 已存在进行中的变更单
		DS-->>AS: 返回 existingChangeId
		AS-->>C: existed=true, changeId
		C-->>FE: 200 OK (复用已有变更)
		FE-->>U: 跳转已有变更详情
	else 可新建变更
		DS->>R: 保存新变更记录 + 写入变更前版本
		R-->>DS: 返回 newChangeId
		DS-->>AS: 返回 newChangeId
		AS-->>C: existed=false, changeId
		C-->>FE: 200 OK (创建新变更)
		FE-->>U: 跳转新变更详情
	end

	Note over C,FE: 出口：统一返回 changeId、是否复用、提示信息
```

### 4.2 时序点说明（建议逐条填写）
1. 触发条件：谁在什么场景下发起变更。
2. 前置校验：权限、参数、数据状态、并发/幂等规则。
3. 关键写操作：哪些表/聚合被修改，是否记录变更前版本。
4. 分支策略：已存在草稿/进行中单据时如何处理。
5. 返回契约：成功/复用/失败返回结构与错误码。

### 4.3 长流程处理（流程过长时必填其一）
当完整流程较长时，不要求把所有细节都画在一张图里，优先展示“本次改动影响的时序点”：
1. 主时序图：仅保留端到端主链路（5-9个关键交互）。
2. 改动时序图：单独新增“变更点子流程图”，只画新增或修改的调用链。
3. 注释标记：在图中用 `Note over` 明确“新增/调整/兼容旧逻辑”位置。
4. 差异说明：在图下补充“改动前 -> 改动后”两到三条对照说明。

#### 4.3.1 改动点子流程示例（可选）
```mermaid
sequenceDiagram
	participant C as Controller
	participant S as Service
	participant D as Domain

	Note over C,D: 仅展示本次新增的并发校验与版本写入
	C->>S: change(cmd)
	S->>D: checkVersion(cmd.version)
	alt 版本冲突
		D-->>S: throw VERSION_CONFLICT
		S-->>C: 409 + 错误码
	else 校验通过
		S->>D: saveWithPreVersion(cmd)
		D-->>S: changeId
		S-->>C: 200 + changeId
	end
```
