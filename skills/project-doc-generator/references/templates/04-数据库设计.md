## 一、核心数据表

### 1.0 统一设计约束（必填）
1. 若为新增数据表，必须包含以下固定字段：`create_time`、`update_time`、`create_user_id`、`update_user_id`、`is_deleted`。
2. 本次设计中的新增字段、修改字段，必须定义为 `NOT NULL`。
3. 字段允许配置默认值；如业务存在“不确定值”场景，应通过业务约定值或默认值表达，不允许使用可空字段规避约束。

固定字段建议如下：

| 字段名 | 类型（示例） | 约束 | 默认值（示例） | 说明 |
|--------|---------------|------|----------------|------|
| create_time | datetime | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| update_time | datetime | NOT NULL | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| create_user_id | bigint | NOT NULL | 0 | 创建人ID |
| update_user_id | bigint | NOT NULL | 0 | 更新人ID |
| is_deleted | tinyint(1) | NOT NULL | 0 | 软删除标记：0-未删除，1-已删除 |

### 1.1 表A（TABLE_A）

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | bigint | PRIMARY KEY, NOT NULL | - | 主键ID |
| name | varchar(128) | NOT NULL | '' | 名称 |
| create_time | datetime | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| update_time | datetime | NOT NULL | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| create_user_id | bigint | NOT NULL | 0 | 创建人ID |
| update_user_id | bigint | NOT NULL | 0 | 更新人ID |
| is_deleted | tinyint(1) | NOT NULL | 0 | 软删除标记 |

### 1.2 字段变更清单（新增/修改必填）

| 变更类型 | 表名 | 字段名 | 类型 | 变更后约束 | 默认值 | 变更说明 |
|----------|------|--------|------|------------|--------|----------|
| 新增字段 | TABLE_A | status | tinyint | NOT NULL | 0 | 状态：0-草稿，1-生效 |
| 修改字段 | TABLE_A | name | varchar(256) | NOT NULL | '' | 扩容字段长度 |

校验要点：
1. 新增字段：必须明确 `NOT NULL` 与默认值策略。
2. 修改字段：若涉及类型、长度、语义调整，变更后必须保持 `NOT NULL`。
3. 若历史数据可能不满足约束，需在文档中补充“数据修复/回填方案”。
