## 三、部署步骤

### 3.1 首次部署

1. **准备环境**
   - 安装 JDK 17+：`yum install java-17-openjdk` 或 `apt install openjdk-17-jdk`
   - 确认 `java -version` 输出正确版本

2. **初始化数据库**
   - 创建数据库：`CREATE DATABASE xxx_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
   - 执行建表脚本：`mysql -u root -p xxx_db < db/init.sql`
   - 执行本次变更脚本（如有）：`mysql -u root -p xxx_db < db/migration/V1.0.0__init.sql`

3. **部署应用**
   - 上传 JAR 包到服务器：`scp target/app.jar user@server:/opt/app/`
   - 创建配置目录：`mkdir -p /opt/app/config`
   - 放置配置文件：将 `application.yml` 放入 `/opt/app/config/`

4. **启动应用**
   ```bash
   nohup java -jar /opt/app/app.jar \
     --spring.config.location=/opt/app/config/application.yml \
     > /opt/app/logs/app.log 2>&1 &
   ```

5. **验证部署**
   - 检查进程：`ps aux | grep app.jar`
   - 检查端口：`netstat -tlnp | grep 8080`
   - 健康检查：`curl http://localhost:8080/actuator/health`
   - 预期返回：`{"status":"UP"}`

### 3.2 更新部署

1. 备份当前版本：`cp /opt/app/app.jar /opt/app/backup/app.jar.$(date +%Y%m%d%H%M)`
2. 停止旧进程：`kill -15 $(cat /opt/app/app.pid)`
3. 上传新 JAR 包覆盖
4. 执行数据库变更脚本（如有新增）
5. 启动新版本应用
6. 验证健康检查通过

### 3.3 回滚步骤

1. 停止当前版本
2. 将备份 JAR 包复制回 `/opt/app/app.jar`
3. 若涉及数据库回滚，执行对应回滚脚本
4. 启动旧版本应用
5. 验证健康检查通过

## 四、运维监控

### 4.1 关键监控指标

| 指标 | 采集方式 | 告警阈值 | 说明 |
|------|----------|----------|------|
| 应用存活 | `/actuator/health` 探活 | 连续 3 次失败 | 进程是否存在 |
| 接口响应时间 | APM / 日志分析 | P95 > 3s | 业务接口性能 |
| 接口错误率 | APM / 日志分析 | 5分钟内 > 5% | 业务异常比例 |
| JVM 堆内存使用 | `/actuator/metrics/jvm.memory.used` | > 80% | 内存泄漏风险 |
| 数据库连接池 | `/actuator/metrics/hikari.connections.active` | > 80% 最大连接数 | 连接池耗尽 |
| 磁盘使用率 | 系统监控 | > 85% | 日志写满风险 |

### 4.2 日志说明

| 日志文件 | 路径 | 内容 |
|----------|------|------|
| 应用日志 | `/opt/app/logs/app.log` | 业务日志、异常堆栈 |
| 访问日志 | `/opt/app/logs/access.log` | HTTP 请求记录（如启用） |
| GC 日志 | `/opt/app/logs/gc.log` | JVM GC 详情（如启用） |

### 4.3 常见运维操作

```bash
# 查看实时日志
tail -f /opt/app/logs/app.log

# 搜索错误日志
grep "ERROR" /opt/app/logs/app.log | tail -50

# 重启应用
kill -15 $(cat /opt/app/app.pid)
nohup java -jar /opt/app/app.jar > /opt/app/logs/app.log 2>&1 & echo $! > /opt/app/app.pid

# 查看 JVM 信息
jstat -gc $(cat /opt/app/app.pid) 1000 5
```

# 第二部分：用户手册

## 一、功能操作指南

### 1.1 变更创建

**操作路径**：目标详情页 → 点击"发起变更"按钮 → 填写变更参数 → 点击"提交"

**操作步骤**：
1. 进入目标实体的详情页面
2. 点击页面右上角的"发起变更"按钮
3. 在弹出的变更表单中填写：
   - **变更类型**：从下拉列表中选择（如：修改、删除、迁移）
   - **变更原因**：必填，简要描述变更目的
   - **变更参数**：根据变更类型动态展示的表单项
4. 点击"提交"按钮
5. 系统提示"变更创建成功"并自动跳转到变更详情页

**注意事项**：
- 同一目标实体同时仅允许一个进行中的变更单
- 若已存在进行中的变更单，系统会自动复用而非创建新的
- 变更创建后状态为"草稿"，需后续提交审批

### 1.2 变更审批

**操作路径**：变更详情页 → 点击"提交审批"→ 审批人操作

**操作步骤**：
1. 在变更详情页确认变更内容无误
2. 点击"提交审批"按钮
3. 审批人在待办列表中找到该审批任务
4. 审批人可选择"通过"或"驳回"
5. 通过后变更生效，驳回后变更回到草稿状态

### 1.3 变更作废

**操作路径**：变更详情页 → 点击"作废"按钮

**操作步骤**：
1. 进入变更详情页（仅草稿状态可作废）
2. 点击"作废"按钮
3. 在确认弹窗中点击"确认"
4. 变更状态变为"已作废"，操作不可逆

## 三、常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 点击"发起变更"无响应 | Token 过期 | 刷新页面或重新登录 |
| 提交时报"已存在进行中的变更单" | 之前创建过变更单但未完成 | 在目标实体的变更记录中找到该变更单继续操作，或先作废后再新建 |
| 审批不通过但未说明原因 | 审批人备注信息未填写 | 联系审批人获取驳回原因 |
| 变更生效后数据未更新 | 后端异步处理未完成或失败 | 等待 30 秒后刷新，若仍未更新联系技术支持 |
| 页面数据加载慢 | 数据量大或网络延迟 | 缩小查询时间范围，或检查网络连接 |
| "无权限访问"提示 | 当前账号无对应模块权限 | 联系管理员申请权限 |
| 并发操作提示"请稍后重试" | 同一目标被多人同时操作 | 等待 3 秒后重新操作 |
| 作废按钮灰色不可点击 | 变更单状态非草稿 | 只有草稿状态的变更单可以作废 |
```
